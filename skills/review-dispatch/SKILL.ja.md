# Review Dispatch スキル

観点別のレビューを**エージェントに並列で委譲**し、指摘表を回収する。

**このスキルの成果物は指摘表（report-<perspective>.md）である。統合・採否はしない。コードは 1 行も変えない。**

## 原則

- **オーケストレータはレビューしない。** 判断はすべてレビュアー（子エージェント）が行う。
- **1 波の観点は全て 1 回の呼び出しで並列起動する。** 順に回すと時間が積み上がる。
  委譲の手段は問わない（subagent / tmux / herdr、並列起動できるものなら何でも）。
- **待つのは 1 回の呼び出しで全レビュアー分。** `sleep` ポーリング禁止。完了通知（`--wait`）で待つ。
  1 本ずつ待つと、速く終わった分が回収されないまま塩漬けになる。
  「1 コール」は**1 回のツール呼び出しが全部の完了で返る**という意味であり、
  「wait コマンドに複数引数を与える」ことではない（`herdr agent wait` は 1 引数しか受けない。
  実行形は手順 3）。
- **レポートはレビュアー自身に書かせる。** 回収は `report-<perspective>.md` の読み出しであって、
  2 回目のプロンプトではない。「今から表をファイルに書き出して」と頼んではならない。
  プロンプトが既にファイル名を指定しており、レビュアーごとの往復 1 回は波全体より高くつく。
- **レビュアーは全員名前にする。** 無名ペイン（`wS:pG`）は待てず回収できない。
- **予算はプロンプトに書く。** ここだけに書いた数字は何も動かさない。
  レビュアーは受け取った文面に数字が無ければ数字で止まらない。
- **観点は判断であり、作業指示ではない。** 列挙された検証ジョブのチェックリストは
  レビュアーを実行者に変える。「何を見るか」を書き、「何個確認するか」を書かない。

## 手順

1. **観点を選ぶ。** 必要な観点だけ。上限 3 本（超えるなら 2 波に分ける）。

   | 観点           | 必要になる条件                          | thinking |
   | -------------- | --------------------------------------- | -------- |
   | コード         | 常に                                    | medium   |
   | セキュリティ   | 認証・認可・外部入力・秘密情報に触れる  | high     |
   | テスト         | テストの追加・変更がある                | medium   |
   | アーキテクチャ | 集約境界・ドメイン層・公開 API に触れる | high     |
   | 仕様           | 要件定義・受け入れ条件がある            | medium   |

   「念のため」で `thinking` を上げない。表の値がそのまま正である。

2. **プロンプトを作る。** 1 観点 1 プロンプト。`templates/prompt.md` から始めて
   `{{...}}` をすべて埋め、`/tmp/review-<label>/prompt-<perspective>.md` に保存する。
   テンプレートには予算ブロック・禁止事項・出力形式が入っているので、書き写さず
   プレースホルダを埋めて観点チェックリストを足す:

   | プレースホルダ    | 値                                            |
   | ----------------- | --------------------------------------------- |
   | `{{PERSPECTIVE}}` | Code / Security / Tests / Architecture / Spec |
   | `{{TICKET}}`      | チケット uid                                  |
   | `{{EVIDENCE}}`    | `/tmp/review-<label>/evidence.md`             |
   | `{{DIFF}}`        | `/tmp/review-<label>/diff.patch`              |
   | `{{FILES}}`       | `/tmp/review-<label>/files`                   |
   | `{{REPORT}}`      | `/tmp/review-<label>/report-<perspective>.md` |
   | `{{CHECKLIST}}`   | 観点の判断する問い（最大 4 項目）             |

   **予算ブロックは省略できない**。どうしても雛形を使わずに書くなら、これを含める:

   ```text
   ## 予算
   - ツール呼び出しは 15 回まで。超えそうなら打ち切って、残りを「未確認事項」に 1 行で書け。
   - 全体 60 行以内。表の後に書けるのは「未確認事項:」だけ（最大 3 行）。
   - 目安 8 分。判断は evidence.md の中で完結させる。

   ## 禁止
   - evidence.md の「3. Verified facts」を再検証しない。§3.1 が報告しているコマンドは再実行しない。
   - インタプリタ・プローブを走らせない（node -e / python -c / tsx / sqlite3 / テストランナー）。
   - ファイルの作成・編集・削除は成果物ディレクトリの report-<perspective>.md 1 つだけ。
     それ以外のファイルは作らない（作業ツリー内の一時ファイルも含む）。
   - evidence.md とリポジトリの再探索をしない。§3 に無いことは「未確認事項」に書く。
   ```

   以前は「ファイルを作成しない」と禁止しておいて、後から書き出しを頼んでいた。
   レビュアーは従うことと提出することを両立できず、回収が 2 回目のプロンプトになっていた。
   プロンプトでレポート先（`{{REPORT}}` = `/tmp/review-<label>/report-<perspective>.md`）を
   名指しし、禁止事項からその 1 つだけを除外する。どちらかが欠けたプロンプトは
   `check-prompt.sh` が落とす。

   パックに diff は入っていないが、`{{DIFF}}` と `{{FILES}}` は埋める。埋めないと
   レビュアーは指摘の行がどこから来たか推測する。チェックリストは **最大 4 項目**で、
   実行する手順ではなく判断する問いとして書く —— 行番号の列挙、既定値のリスト、
   「本当に X を塞げているか確認しろ」は探索の種になるので書かない。

   重大度は**自分の観点から見た影響**で付けさせる。3 観点が同じ原因を NITS / NITS / IMO と
   別々に付けるのは観点設計のサインであり、指摘 3 件ではない。最終重大度は統合側が決めるので、
   レビュアーに先取りの裁定をさせない。テンプレートに 1 行入っている。消さない。

   ```text
   | 重大度 | 場所 | 指摘 | 根拠 | 修正案 |
   |---|---|---|---|---|
   | MUST | app/foo.ts:42 | … | … | … |
   ```

   - 重大度: MUST（修正しないと目的未達成・重大な不具合）/ NITS（挙動は同じだが直した方がよい）/
     IMO（修正した方がよりベターな実装になる可能性のある提案）
   - 場所は `path:line`。行が特定できなければ `path` のみ。
   - 同じ原因の複数箇所は代表 1 行に他を併記（`app/a.ts:12`（同: `app/b.ts:30`））。
   - 該当なしなら `指摘なし` とだけ。
   - 出力は 60 行まで。表の後に書いてよいのは `未確認事項:` だけ（最大 3 行）。

   投入前にプロンプトをゲートする。未置換のプレースホルダ、予算の欠落、逃げ道の欠落、
   プローブ禁止の欠落、evidence パスの欠落、`report-<perspective>.md` の欠落、
   成果物ディレクトリを除外していない禁止事項、観点を絞っていない重大度行、
   そして隣にある `collect-evidence.sh` の `DO_NOT_DISPATCH` で失敗する。
   失敗は全件を 1 回で報告する。

   ```bash
   SKILL_DIR=<このスキルのディレクトリ>
   "$SKILL_DIR/scripts/check-prompt.sh" /tmp/review-<label>/prompt-*.md   # exit 1 = 投入しない
   ```

   指摘された内容を直す。迂回して投入しない。

3. **並列起動する。** 観点の数だけレビュアーを、**1 回の呼び出しで**並列に起動する。
   レビュアーは自分で `report-<perspective>.md` を書く。回収はそのファイルを読むだけ。

   **herdr**: `agent wait` は `<TARGET>` を 1 つしか受けない
   （`herdr agent wait rev-code rev-spec` は `unexpected argument` の使用エラーになる）。
   1 回のシェル呼び出しに束ねる —— 背景 `&` と 1 つの `wait` が「1 コール」である:

   ```bash
   # 1 回のツール呼び出し。各 `agent prompt --wait` はそのレビュアーの完了で返り、
   # シェルの `wait` が全部を合流させる。名前の無いペイン（wS:pG）はそもそも待てない。
   for p in code spec tests; do
     herdr agent prompt "rev-$p" "$(cat /tmp/review-<label>/prompt-$p.md)" --wait --timeout 900000 &
   done
   wait
   ```

   起動前に名前を確認する:

   ```bash
   herdr agent list   # 全レビュアーに name があること
   ```

   subagent でも同じ。1 観点 1 子の workflow 呼び出しにするか、束に対して 1 回待つ。

   **`sleep` してポーリングしない。** `working` のままのレビュアーのペインを読まない。
   終わったレビュアーを 2 回目に叩いて表を書かせない —— もう自分で書いている。

4. **回収する。** 観点ごとに `report-<perspective>.md` を 1 回読む。もし古いプロンプトで
   出力先を指定せずに投入していたら、`agent read <name> --source recent-unwrapped` の 1 回で
   本文を取り、ペイン装飾を落として自分でファイルに書く（レビュアーごとに 2 回目のプロンプトを
   投げるのではない）。全レポートがディスクに揃ったら終わり。内容の判断はしない。

## 予算

- レビュアー 1 本のツール呼び出し: 15 回まで — この数字はここだけでなく**プロンプトに書く**
- レビュアー 1 本の出力: 60 行まで
- レビュー全体の wall-clock: 10 分（1 本の待ち上限 15 分）
- 3 観点 1 波のツール呼び出し合計: 45 回。これを超えた波は、レビューではなく探索をした。
  予算を上げず、次の順で診断する:

1. **予算はプロンプトに入っていたか。** 入っていなければそれが原因。プロンプトを直す。
2. **事実パックが 15 KB に収まっていたか。** 超えているなら `review-prepare` の手順 1 の失敗で
   あって、レビュアーの失敗ではない。
3. **チェックリストが項目を列挙していないか。** 判断の問いが 4 個を超えていたら、
   それは作業指示書になっている。
4. **レビュアーが 2 ターン以上になったか。** レポートを書かせる 2 回目のプロンプトや、
   プロンプトが答えられなかった問いへの追加ターンは、プロンプトと文脈を丸ごと再送する。
   実測ではレビュアー 1 本あたり 2 往復（各 3.7k / 45k トークン前後）を払い、成果はゼロだった。
   直すのはレビュアーではなくプロンプト。
5. **パックに無い素材を必要としたか。** それは事実パックの穴である。記録し、次の実行で
   `evidence.md` に戻す。
6. ここまで来て初めてモデルや `thinking` を検討する。しかも上の表の範囲内で。

15 回で打ち切ってパックから答えたレビュアーは、失敗ではなく成功である。

## ゲートの自己テスト

`scripts/check-prompt.sh` の各ルールには `scripts/self-test.sh` の検証がある（通るべき例と
落ちるべき例を 1 つずつ）。`check-prompt.sh` を直したらこれを実行する。黙って効かなくなった
ルールは、ルールが無いより悪い —— チェックに見えるからである。

```bash
"$SKILL_DIR/scripts/self-test.sh"
```

## 完了条件

- 全観点の `report-<perspective>.md` が `/tmp/review-<label>/` に存在する
- レポートはレビュアー自身が書いており、ファイルを作らせるために 2 回目のプロンプトをしていない
- 波の間、全レビュアーを名前で待った（無名ペインからの回収をしていない）
- 投入したプロンプトに対して `scripts/check-prompt.sh` が exit 0 した
- **diff に変更が無い**
